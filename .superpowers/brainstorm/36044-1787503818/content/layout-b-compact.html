Same full-width idea, but every input is sized to its actual content instead of stretching to fill an equal 1/N share. Short fields (GST%, Qty, Code) shrink; long ones (Product Name) get the freed-up space. Result: more fields fit per row, so there are fewer rows overall.

Note the count: the previous version needed 5 rows for Product+Pricing+Classify. This version does the same in 2 rows — Product/Barcode/GST on one line, then all 8 pricing+classify fields (Rate, Qty, MRP, Retail, SP, Category, Unit, HSN) on one line, sized by how much text they actually hold. Variants/Batches collapse into two small "Off" toggles side-by-side instead of two separate stacked sections.

Why this is tighter

  • Fields sized to content (Qty/GST%/HSN are 3-4 characters wide, not stretched to match "Product Name")
  • Variants + Batches toggles sit side-by-side on one line instead of two full-width blocks — they only expand into their own row of inputs when switched on
  • Category/Unit/HSN folded into the same row as Rate/Qty/MRP/Retail/SP — one continuous "fill in the details" row instead of a separate numbered section

Watch for

  • On a narrower laptop screen (13"), 8 fields on one row may need to wrap to 2 rows anyway — still better than the current 3+ rows, and Tailwind's responsive grid handles this automatically
